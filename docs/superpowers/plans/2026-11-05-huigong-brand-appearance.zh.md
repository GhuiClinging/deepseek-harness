# 辉总品牌外观实施计划

English | [中文](2026-11-05-huigong-brand-appearance.md)

> 面向代理执行者：使用 superpowers:executing-plans 在当前会话持续实施。

**目标：** 交付本机 ARM64 测试应用，提供精简网页入口、可见 IM 入口、不透明的独立页面、本地背景轮换和固定照片品牌图标。

**架构：** 复用通用设置插件管理外观配置、经过认证的 Connection Fetch 图库和可清理的浏览器控制器。Conversation 页头提供根级操作槽位；现有侧栏和 Conversation 容器提供局部图片挂点。桌面品牌在完整性封装前准备图片，并初始化应用默认值，保留用户显式选择。

**技术栈：** 沿用 TypeScript、Cordis、React、Schemastery、Connection Fetch 路由、Sharp、Electron 和 electron-builder；不新增外部依赖。

**规格：** 用户于 2026-11-05 确认推荐方案并授权处理细节：右上角仅图标的浏览器入口，提示“跳转网页版”；IM 默认显示；独立页面保持原底色；背景分别每随机 5–15 分钟变化；精选内置图片之前先测试外置 `Desktop/213`；两处品牌图标先共用固定测试图片。

## 约束与决策

- 在相关的未提交功能分支继续，保留既有品牌改动；不提交、推送、删除、修改密钥、公开发布或部署生产环境。
- 不修改原始照片。测试图库副本保存在忽略的构建资源中；源码精选图片留待用户后续选择。
- 使用经过认证且仅限拥有者的 `/api/brand-appearance/catalog`、`/api/brand-appearance/image` 和 `/api/brand-appearance/logo`；不暴露任意本地路径或未认证文件。
- 图片仅限所选目录内有大小限制的普通 PNG/JPEG/WebP 文件；拒绝链接与目录穿越，短暂失败时保留上一张图。
- 恢复普通全局主题变量；照片仅作用于 Conversation 和侧栏容器。独立面板及通过 portal 展示的设置保持原有底色。
- 使用源码品牌默认值，保留已保存的 IM 显示选择；停用被替代的本地主题但不删除。
- 参考 [vscode-background](https://github.com/shalldie/vscode-background)（MIT）的目录展开、分区背景和随机轮播。借鉴设计；其 VS Code HTML 补丁与协议不适用于 Harness，对应操作复用 Harness Connection 和槽位服务。

## 审查重点

- 空白 Conversation 仍有浏览器图标，且不显示认证 Token 或网址。
- 目录移动、为空、损坏、链接或不可读时，不暴露任意文件，也不清空已接受的背景。
- 目录编辑、重连、延迟请求、定时器清理和重复注册只保留一个有效控制器，避免陈旧图片。
- 安装升级后既有主题、凭据、IM 账号和显式入口选择仍可恢复。
- 实际包内图标和图库通过 ASAR 准备，浅色与深色模式的原有弹窗底色保持不透明。
